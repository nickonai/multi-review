# multi-review

**Мульти-ИИ ревью одного артефакта несколькими моделями параллельно.**

`multi-review` — это [Agent Skill](https://agentskills.io) (открытый стандарт
`SKILL.md`), который запускает несколько внешних AI-CLI (**codex**, **gemini**,
**claude**) параллельно по одному и тому же материалу. После этого ведущий агент
**проверяет каждую находку по реальному коду или тексту** и отсеивает ложные и
преувеличенные — то есть не пересказывает вам всё, что выдали модели, а отделяет
настоящие проблемы от шума.

Ревьюить можно как **код** (diff ветки, незакоммиченные изменения, рабочее
дерево), так и **любой текст** — спецификацию, план, статью, системный промпт,
юридический или маркетинговый документ, README, RFC и т.д.

> **Зачем.** Ценность нескольких ревьюеров — в **разнообразии слепых зон**: одна
> модель пропускает то, что видит другая. Риск — **галлюцинированные, раздутые
> или переусложнённые находки**. Скилл кодифицирует обе стороны: он не доверяет
> внешним моделям на слово, а проверяет каждую находку по фактическому
> артефакту, прежде чем что-то рекомендовать.

Лицензия — [MIT](LICENSE). Скилл бесплатный, открытый, его можно свободно
скачивать, копировать и дорабатывать.

## Как это работает

1. Скилл определяет режим: **код** (git-изменения) или **текст** (отдельный
   файл/документ).
2. Локальный shell-скрипт собирает лёгкий «пакет ревью» в `/tmp/multi-review/`:
   корень контекста, список файлов, применимые `AGENTS.md` / `CLAUDE.md` /
   `GEMINI.md` и готовый компактный промпт. Большие файлы **не** передаются
   моделям целиком — ревьюеры сами открывают локальные файлы.
3. Каждый внешний CLI запускается отдельно, параллельно, с таймаутом и
   изоляцией сбоев (один упавший ревьюер не ломает остальных).
4. Агент-ведущий **проверяет каждую находку по коду/тексту**, отклоняет
   галлюцинации и переусложнения и выдаёт сгруппированный отчёт: «к
   исправлению», «только для сведения», «отклонено».

Промпты, уходящие внешним моделям, — на английском (так ревью кода стабильнее).
Документация скилла и финальный отчёт пользователю — на русском.

## Требования

- **bash**, **git**, **python3**, **perl** (есть по умолчанию на macOS и
  большинстве Linux).
- Хотя бы **один** из внешних AI-CLI, установленный и авторизованный:
  - [`codex`](https://developers.openai.com/codex/) — OpenAI Codex CLI
  - [`gemini`](https://geminicli.com/) — Google Gemini CLI
  - [`claude`](https://code.claude.com/docs/) — Claude Code CLI

Чем больше CLI доступно, тем выше покрытие. Если доступен только один — скилл
работает, но выигрыш от разнообразия теряется.

## Платформы (macOS / Linux / Windows)

Скрипты скилла — это **bash на Unix-инструментах**. Поэтому:

| Платформа | Статус |
|---|---|
| **macOS** | ✅ Работает из коробки |
| **Linux** | ✅ Работает из коробки |
| **Windows + WSL** | ✅ Работает (внутри WSL это Linux) |
| **Windows + Git Bash** | ✅ Работает (обёртка сама пробует `python3` и `python`) |
| **Windows, только cmd / PowerShell** | ⚠️ Bash-скрипты напрямую не запускаются — см. ниже |

**Важно:** скрипты — это лишь удобная обёртка, а не обязательное условие. Если на
вашей машине они не запускаются (нет `bash`, `python` или `perl`), агент **не
зависает**: он переходит на встроенный ручной запасной путь
([`multi-review/references/fallback.md`](multi-review/references/fallback.md)) и
делает ту же работу своими инструментами — собирает цель ревью через git/чтение
файлов, составляет промпт и запускает каждый внешний CLI напрямую. То есть
мульти-ревью отрабатывает даже там, где обёртка недоступна.

Для Windows проще всего поставить скилл и запускать агента **внутри WSL** или
**Git Bash** — тогда работает «быстрый» путь со скриптами. Сами модели
(`codex`, `gemini`, `claude`) кросс-платформенные и работают на любой ОС.

## Установка

Это скилл стандарта `SKILL.md`. Он работает нативно в **Claude Code**, **Codex
CLI**, **Gemini CLI** и **Cursor**.

### Самый простой способ: попросить агента

Если у вас уже есть ИИ-агент (Claude Code, Codex, Cursor и т.п.), не нужно
ничего копировать вручную. Просто дайте ему ссылку на этот репозиторий и
попросите установить скилл, например:

> Установи себе вот этот скилл: https://github.com/nickonai/multi-review
> Положи его в директорию скиллов и убедись, что он подхватился.

Агент сам склонирует репозиторий, скопирует папку `multi-review/` в нужную
директорию скиллов (`~/.claude/skills/`, `~/.agents/skills/` и т.п.) и проверит
установку. Дальше можно сразу пользоваться.

Если предпочитаете сделать всё руками — ниже инструкции под каждый агент.

### Установка вручную

Сначала склонируйте репозиторий (один раз):

```bash
git clone https://github.com/nickonai/multi-review.git
```

Сам скилл лежит в подпапке `multi-review/multi-review/` (внутри неё — `SKILL.md`,
`references/`, `scripts/`). Установка везде сводится к копированию этой папки в
директорию скиллов нужного агента.

> Многие агенты (Codex, Gemini, Cursor) читают **общий** путь
> `~/.agents/skills/`. Если установить скилл туда — его подхватят сразу
> несколько инструментов:
>
> ```bash
> mkdir -p ~/.agents/skills
> cp -r multi-review/multi-review ~/.agents/skills/multi-review
> ```

### Claude Code

Персональная установка (для всех проектов):

```bash
mkdir -p ~/.claude/skills
cp -r multi-review/multi-review ~/.claude/skills/multi-review
```

Установка на проект (закоммить, чтобы поделиться с командой):

```bash
mkdir -p .claude/skills
cp -r /path/to/multi-review/multi-review .claude/skills/multi-review
```

Дальше в Claude Code: напишите `/multi-review` или просто попросите «сделай
мульти-ревью». Проверить установку: спросите «какие скиллы доступны?».

### Codex CLI (OpenAI)

Codex автоматически находит скиллы в `~/.agents/skills/` (глобально) или
`.agents/skills/` (в проекте):

```bash
mkdir -p ~/.agents/skills
cp -r multi-review/multi-review ~/.agents/skills/multi-review
```

Codex подхватит скилл и будет вызывать его по описанию из `SKILL.md`.

### Gemini CLI (Google)

Gemini читает `~/.gemini/skills/` или общий `~/.agents/skills/`:

```bash
mkdir -p ~/.gemini/skills
cp -r multi-review/multi-review ~/.gemini/skills/multi-review
```

Затем в интерактивной сессии включите скилл:

```
/skills enable multi-review
```

### Cursor

Cursor (2.4+) находит скиллы автоматически в `.cursor/skills/` или
`.agents/skills/` (а также читает `~/.claude/skills/` для совместимости):

```bash
mkdir -p .cursor/skills
cp -r /path/to/multi-review/multi-review .cursor/skills/multi-review
```

Для глобальной установки используйте `~/.cursor/skills/` вместо `.cursor/skills/`.

### Manus

Manus — облачный агент, у него нет локальной папки. Он поддерживает тот же
стандарт Agent Skills: импортируйте `SKILL.md` (и вложенные файлы) через
интерфейс Manus → Skills, после чего вызывайте скилл командой `/multi-review`.
Актуальный способ импорта смотрите в документации Manus.

### Другие агенты (через AGENTS.md)

Для агентов, которые читают [AGENTS.md](https://agents.md), но пока не
поддерживают `SKILL.md` (Aider, Zed, Warp, Jules и др.), можно вставить
инструкции из `multi-review/SKILL.md` в корневой `AGENTS.md` вашего репозитория.
Это не полноценный скилл (нет автозагрузки по требованию), но рабочий фолбэк.

## Как пользоваться

После установки просто попросите агента сделать мульти-ревью — скилл сработает
по описанию. Примеры запросов:

- «сделай **мульти-ревью** текущей ветки»
- «**проверь несколькими моделями** этот diff»
- «нужно **второе мнение** по вот этой спецификации: `docs/spec.md`»
- «**кросс-ревью** моего системного промпта `prompt.md`»
- «прогони **external review** черновика лендинга `landing.md`»

Скилл сам определит режим (код или текст). Если запрос неоднозначный
(«проверь это») — агент один раз уточнит: код или текст.

Запускать скрипты вручную обычно не нужно — агент делает это сам. Скилл **не
использует переменные окружения**: всё передаётся аргументами, а рабочая
директория всегда `/tmp/multi-review`. При желании можно собрать пакет ревью
напрямую:

```bash
# Режим кода (из корня git-репозитория; необязательный аргумент — базовая ветка):
~/.claude/skills/multi-review/scripts/build-code-review-pack.sh          # сравнить с main
~/.claude/skills/multi-review/scripts/build-code-review-pack.sh develop  # сравнить с develop

# Режим текста (первый аргумент — тип контента, дальше — файлы):
~/.claude/skills/multi-review/scripts/build-text-review-pack.sh spec /abs/path/to/spec.md
```

Тип контента — одно из: `article`, `spec`, `plan`, `prompt`, `legal`,
`marketing`, `generic`. Подробности команд — в
[`multi-review/references/cli-commands.md`](multi-review/references/cli-commands.md).

## Безопасность

- Скрипты сборки пакета **редактируют распространённые шаблоны секретов**
  (API-ключи OpenAI/Anthropic/Google, токены GitHub/GitLab/Slack, ключи AWS,
  JWT, строки подключения к БД, приватные ключи) в любом сгенерированном
  вспомогательном материале перед отправкой моделям.
- Ревьюеры работают **только на чтение**: им явно запрещено редактировать
  файлы, коммитить, пушить или менять рабочее дерево.
- Полный diff в режиме кода **не сохраняется** в финальном пакете и не
  вставляется в промпты Codex/Claude.
- Тем не менее редактирование секретов — best-effort. Не запускайте мульти-ревью
  на репозиториях с незашифрованными боевыми секретами.

## Структура репозитория

```
multi-review/
├── README.md            ← этот файл
├── LICENSE              ← MIT
└── multi-review/        ← сам скилл (копируется в директорию скиллов агента)
    ├── SKILL.md         ← точка входа: назначение, режимы, рабочий процесс, правила
    ├── references/
    │   ├── cli-commands.md   ← команды CLI, сборка пакетов, обработка ошибок
    │   ├── prompt-code.md    ← заметки по промпту режима кода
    │   ├── prompt-text.md    ← заметки по промпту режима текста
    │   ├── triage.md         ← разбор находок и формат финального отчёта
    │   └── fallback.md       ← платформы и ручной запасной путь (Windows и т.п.)
    └── scripts/
        ├── build-code-review-pack.sh   ← сборка пакета для режима кода
        ├── build-text-review-pack.sh   ← сборка пакета для режима текста
        └── run-external-reviewer.sh    ← обёртка: таймаут + изоляция сбоев
```
